# Phase 1 — AI 분석 검증 기록

> 목적: AI(Claude Code)가 수행한 코드베이스 분석의 검증 방법과, 분석 과정에서 발견·수정된 오류를 기록한다. (프로젝트 원칙: "AI 분석 결과를 실제 코드와 대조, 잘못된 설명 및 추론 내용 기록")

## 1. 분석 방법

- 메인 소스 전 파일(약 6,600라인) 중 엔티티·서비스·리포지토리·설정·보안·웹소켓 전부와 주요 DTO를 직접 읽음(요약 추론이 아니라 원문 기반).
- 동작 검증이 가능한 것은 Phase 0 실측과 교차 확인(예: 레벨업 보상 코인 20 — 로컬 측정 시 테스트로 확인된 값).
- README ERD는 원본 PNG(2346×1219)를 내려받아 4분할 판독 후 전 테이블·컬럼을 코드와 대조.
- 실행하지 않고 코드만으로 추론한 항목은 문서에 "추정/검증 전/후보"로 명시(R9, R10 등).

## 2. README·기존 문서의 오류/구버전 항목 (실제 코드 우선 원칙으로 기록)

| 항목 | 내용 | 기록 위치 |
|------|------|----------|
| README ERD | routine의 endDate 누락, party의 currentMembers 누락 등 10건 | [01-erd.md](01-erd.md) 대조표 |
| README 구조 설명 | 대체로 일치. 로컬 실행 방법·스케줄러·Redis 용도 미기술 | 사전 분석 보고서 |
| 코드 주석 | `StreakService` 주석은 "일일퀘스트 또는 파티 퀘스트 합산"이라 하나 실제 소스는 DailyQuest 1종뿐 | [domains/streak.md](domains/streak.md) |

## 3. AI 분석 자체의 오류와 교정 (투명성 기록)

| # | 최초 서술(오류) | 교정 | 발견 경위 |
|---|----------------|------|----------|
| 1 | "레벨업 보상 코인은 레벨업 **이전** 레벨 기준" | 레벨업 **후** 레벨 기준(`level += 1` 다음에 `earnCoin(levelUpReward())`) — 1→2 레벨업 시 20코인 | 기존 PartyServiceTest의 기대값(coin=20)과 코드 재독으로 교차 검증 |
| 2 | "파티 수정이 name을 반영하지 않는지 확인 필요"(문제 소지로 기술) | DTO에 name 필드 자체가 없어 **의도된 설계** | PartyUpdateRequestDto 원문 확인 |
| 3 | "toDownloadUrlOrNull은 default 메서드로 추정" | FileStorage 원문으로 확정 | 인터페이스 직접 확인 |

교훈: 엔티티 상태 변경 순서(증가 후 보상 계산)처럼 **한 줄 순서에 의미가 있는 코드**는 요약 기억이 아니라 원문 재확인이 필요. 기존 테스트의 기대값이 훌륭한 교차 검증 수단이 됨.
